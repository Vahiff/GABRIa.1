# Contributing

## Working Style

Use a professional workflow:

1. Create or select an issue.
2. Work in a separate branch.
3. Keep changes focused.
4. Test before opening a pull request.
5. Explain what changed and why.

## Branch Names

Use clear branch names:

- `feature/app-shell`
- `fix/android-build`
- `docs/store-listing`
- `release/1.0.0`

## Commit Style

Use short conventional commit messages:

- `feat: add onboarding screen`
- `fix: correct Android build path`
- `docs: update release checklist`
- `chore: clean project files`

## Pull Request Checklist

- [ ] The change has a clear purpose.
- [ ] The app still builds.
- [ ] UI changes were checked on mobile and desktop sizes when relevant.
- [ ] No secrets or signing files were committed.
- [ ] README or release notes were updated when behavior changed.
